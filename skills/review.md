# Review

Structured code review focused on risks and maintainability.

## Focus areas

1. Correctness and edge cases
2. Security implications
3. Maintainability (naming, complexity, duplication)
4. Test coverage for the changed behavior
5. Performance only if it is likely to matter

## Output

```markdown
## Summary
One sentence on what the change does.

## Risks
- ...

## Suggestions
- ...

## Looks good
- ...
```

Be specific. Avoid generic praise.
