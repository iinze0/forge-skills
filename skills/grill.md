# Grill

Before writing any code, force a short clarification session.

## Rules

1. Do not write implementation code until the user has answered the critical questions.
2. Ask at most 5 questions. Make them sharp.
3. Cover: goal, constraints, edge cases, success criteria, and what "done" looks like.
4. After answers, restate the task in one paragraph and wait for confirmation.
5. Only then start coding.

## Example questions

- What is the single most important outcome of this change?
- What must not break?
- Are there any hard constraints (performance, compatibility, existing patterns)?
- How will we know this is finished?

Never skip this step for new features or non-trivial changes.
